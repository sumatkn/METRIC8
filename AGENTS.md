# METRIC8 contributor and agent instructions

## Read before working

1. Read [scope](docs/SCOPE.md), [rules](docs/RULES_OF_ENGAGEMENT.md), [procedures](docs/PROCEDURES.md), and [current working memory](docs/memory/CURRENT.md).
2. Find the project in [the registry](docs/PROJECTS.md).
3. Read its README, requirements, working memory, and any more-specific AGENTS.md before editing it.

## Working rules

- Follow the user's current task and explicit decisions. Keep work within that scope; ask when an unresolved decision materially changes the result.
- Separate suite responsibilities, individual project requirements, and implementation choices.
- Preserve existing work. Inspect repository state and relevant files before editing; do not overwrite concurrent changes.
- Do not treat proposed procedures, candidate projects, or remembered discussion as approved requirements.
- Verify relevant current files before carrying an earlier decision forward. Record conflicts and ask rather than silently replacing a decision.
- Use project-local documentation for project details and suite documentation for cross-project decisions.
- Record actual validation and its limits. Do not claim in-game verification without running it.
- Keep credentials, personal information, account data, and private conversation transcripts out of this public repository.
- Update working memory after substantive work: current state, decisions, evidence, next steps, and unresolved questions.
- When asked to create, write, or edit a prompt, display the finished prompt in a fenced text block for easy copying.

## Changes and approvals

Routine work explicitly requested by the user is authorized within its scope. Do not repeatedly seek permission for that same work. A draft proposal is not approval to change scope, publish a release, or replace an established requirement.

Do not force-push, rewrite shared history, delete unrelated work, or silently change repository visibility or licensing. New releases must follow a confirmed release procedure or an explicit release request.

## Handoff

Report what changed, what was checked, what remains unverified, and the next material decision. Keep working memory concise and project-relevant.
